# AI 课堂回放与教学分析系统 MVP 产品设计及技术方案

> 文档状态：历史 MVP 方案摘要。这是早期产品与技术方案，用于回看设计演进和交互来源；当前开发、验收、技术选型、数据库和部署均以 `TECHNICAL_MANUAL.md` 为准。

## 目标

第一版聚焦一节课堂视频的证据链式复盘：

```text
教师上传课堂视频
→ 后台生成带时间点逐字稿
→ 合并为 3-5 分钟大段课堂记录
→ AI 基于逐字稿生成证据卡片
→ 教师接受、修改或驳回
→ 只把确认后的结论生成报告
```

核心价值：每条 AI 结论都能回到视频时间点、课堂原文和教师确认记录。

## MVP 范围

必须做：

- 上传课堂视频。
- 记录视频归属、对象地址和处理状态。
- 从视频抽取音频并生成带时间点逐字稿。
- 将逐字稿合并为 3-5 分钟大段课堂记录。
- AI 基于逐字稿生成证据卡片。
- 点击证据卡片跳转到视频时间点和课堂记录段落。
- 教师接受、修改后接受、驳回证据。
- 报告只包含已接受和已修改的证据。
- 支持导出 Markdown 报告。
- 失败时显示原因并允许重试。

第一版不做：

- 课件上传与课件分析。
- 视频画面 OCR。
- 证据画面框选。
- 聊天区识别。
- 学生画像、作业、成绩接入。
- 自动给教师打分。
- 复杂评分体系和学校管理后台。

## 前端交互

桌面端采用左右分屏：

- 左侧 60%：课堂证据工作区。
- 右侧 40%：对话式 AI 任务助手。

左侧包含：

- 视频上传 / 播放区。
- 课堂时间段导航。
- 大段课堂记录编辑区。
- 标记重点、标记困惑、重新分析此段。

右侧包含：

- 6 步任务进度条。
- 对话流。
- 处理过程卡片。
- 证据卡片。
- 人工复核按钮。
- 报告预览卡片。

6 步流程：

```text
对话发起 → 处理过程 → 校订原文 → 核对证据 → 人工复核 → 生成报告
```

## 原文校订原则

不做逐句确认。系统按 3-5 分钟生成大段课堂记录，教师默认不需要确认；只有发现问题时才编辑整段。

课堂记录区支持：

- 中文记录。
- 英文原文。
- 教师点击后生成中英对照；默认不强制翻译整节课。

## AI 分析范围

第一版只基于语音转文字和时间戳分析。支持的维度：

| 维度 | 可用证据 |
| --- | --- |
| 连续讲授 | 教师连续发言时间 |
| 提问质量 | 问句、引导词、追问 |
| 等待时间 | 教师提问结束到学生回答开始的间隔 |
| 反馈质量 | 表扬、纠错、解释、追问 |
| 课堂结构 | 导入、讲授、练习、总结时间段 |
| 节奏风险 | 停顿、短时间大量知识点 |
| 总结闭环 | 结尾段关键词 |

不做强判断：

- 学生是否真正掌握。
- 学生注意力是否集中。
- 教师教学水平高低。
- 学科知识深度正确性判断。

## 建议技术栈

| 模块 | 推荐方案 |
| --- | --- |
| 前端 | 静态原型 / Next.js 后续改造 |
| 后端 | Node.js + Express / NestJS |
| 数据库 | PostgreSQL |
| 队列 | Redis + BullMQ |
| 对象存储 | 腾讯云 COS / 阿里云 OSS |
| 视频处理 | FFmpeg |
| ASR | faster-whisper 或云 ASR |
| LLM | 兼容 OpenAI API 的模型服务 |
| 部署 | 云服务器 + 对象存储 + 数据库 |

## 数据表建议

- `lessons`：课堂任务。
- `lesson_videos`：视频对象存储信息。
- `analysis_tasks`：处理任务与进度。
- `transcript_segments`：带时间点逐字稿。
- `lesson_sections`：3-5 分钟课堂记录段。
- `evidence_cards`：AI 证据卡片。
- `reports`：复盘报告。

## API 建议

```http
POST /api/lessons
POST /api/lessons/{lessonId}/videos/upload-url
POST /api/videos/{videoId}/complete-upload
GET /api/lessons/{lessonId}/status
GET /api/lessons/{lessonId}
PATCH /api/sections/{sectionId}
PATCH /api/evidence-cards/{cardId}/review
POST /api/lessons/{lessonId}/reports
GET /api/reports/{reportId}/markdown
```

## 报告规则

- 只读取 `已接受` 和 `已修改` 的证据。
- 每条结论必须保留时间点和原文依据。
- 语气专业、克制，帮助教师改进。
- 不引入证据之外的判断。
