# 课堂复盘系统轻量工作流底座设计

状态：待用户审阅；尚未实施。日期：2026-10-21。

## 目标与边界

把现有上传→媒体准备→ASR→校对→人工确认→指标→证据抽取→人工审核→报告流程改造成可配置、可恢复、可追踪、可回归的确定性流水线。沿用 NestJS/Fastify API、现有 Worker、PostgreSQL、Next.js 前端；不引入第二套调度平台。人工终审、lesson_format 指标白名单、场景快照和规则优先的 RAG 隔离保持有效。规范稿只进入辅助案例库，课堂原文只用于本课证据定位。

原先暂停的输出修复不直接合并；本次用户要求的 Schema 校验和异常路由需独立实现并验证。模型是否支持服务端 strict JSON Schema 由显式能力配置决定，不将 JSON object 模式称作严格 Schema。

## 方案选择

推荐扩展现有工作流：改动集中、可沿用持久化任务和人工暂停节点。另两个方案是引入 Temporal 等独立引擎（部署与迁移成本偏高），或仅包装模型调用（不能覆盖上传、人工审核和持久化恢复）。本次选择第一个。

## 配置与运行快照

新增版本化 JSON 配置目录：prompts、schemas、workflow、failure-policies、scene-profiles、retrieval。迁移业务 Prompt、窗口大小/重叠数、媒体时长阈值、重试预算、超时、降级策略与 Schema；TypeScript 仅保留执行器和配置结构校验器。现有校对按句数窗口配置，不能误写为已完成时长切片。

API/Worker 启动时校验配置，执行时锁定配置版本及内容哈希，重试沿用同一快照。配置无效时拒绝执行并记录配置错误。Next.js 只经服务端/API 获取公开的展示配置，不读取密钥、内部 Prompt 或数据库凭据。环境变量继续负责密钥及部署地址。

## 持久化与标注回流

扩展 workflow_runs/step_runs：trace_id、attempt、config_hash、error_kind、next_retry_at、lease_until；增加 workflow_failures 与人工复核队列。步骤执行幂等键包含 run、step、输入版本、配置哈希；租约和条件更新防止重复领取及陈旧写入。外部调用按至少一次处理，数据库结果提交幂等，不能宣称外部服务恰好一次。

新增 annotation_events（不可变审核事件）、sample_pool（样例池）、few_shot_releases（版本快照）、regression_sets 与 regression_cases（冻结测试集）。审核与事件/样例候选写入同一事务，重复请求去重。人工通过不直接等同于高质量：候选还需引用核验、场景匹配、字段完整、无敏感内容及去重检查；不合格保留原因。

刷新脚本按场景和单一指标选择有限案例，优先覆盖不同错误类型，生成可追溯 few-shot 版本；运行时最多 1–2 张案例并受字符预算限制。排除本课、本源材料及回归集来源，防止泄漏。负例必须含人工纠正，不能被当作正面教学标准。回归集冻结后数据库约束禁止增删改；扩充需创建新版本，日常标注与刷新脚本不得修改已有冻结版本。

## 失败与恢复

统一使用结构化 Failure：kind、code、traceId、runId、stepKey、attempt、retryable、safeMessage；日志禁止记录密钥和完整课堂文本。

| 类型 | 策略 | 结果 |
|---|---|---|
| schema_invalid | 有限局部重试，预算来自配置 | 耗尽后隔离输出，仅留失败快照，不进入证据列表 |
| business_rule_rejected | 不重试模型 | 进入高优先级人工复核队列；未通过内容不成为可用证据 |
| provider_transient（超时、429、暂时性5xx） | 持久化退避重试，遵循 Retry-After；共享数据库熔断状态 | 达阈值打开熔断，延后任务；半开探测成功后恢复 |
| provider_permanent/configuration/internal | 不伪装成上述三类；明确失败并通知处理 | 保留诊断和人工重试入口 |

Nest 异常过滤器、Provider 适配器、Worker 使用相同错误结构。熔断器只控制依赖服务调用，不阻塞人工审核等无关节点。默认不在失败时生成看似成功的证据。恢复任务校验原文版本、scene_revision、配置快照；输入已变则终止旧结果提交并创建新执行。

## 全链路追踪

视频上传初始化时生成稳定 UUID traceId，写入视频、任务、工作流、步骤、转录、指标、证据、审核事件、报告、失败记录。重试保留 traceId，新增 attemptId/runId；日志统一输出这些字段。服务端校验外部传入标识，不能信任任意请求头。第三方只传允许的请求标识，异步回调靠本地任务映射关联。

历史数据按视频回填稳定 ID；没有视频关联的历史记录不能随意猜配，单独报告未关联数量。提供按 traceId 查询执行轨迹和失败节点的受现有访问控制保护的 API。界面展示简短追踪编号与恢复状态，不展示内部 Prompt。

## 与场景隔离的衔接

先补齐已发现的陈旧指标写入、自动角色变化未失效、报告编辑并发失效漏洞。场景快照贯穿配置选择、检索、生成、校验、保存与报告。按场景记录候选交互指标、被拦截数、最终违规数；增加查询汇总，不宣称已接入外部监控告警平台。

## 验收与交付

1. 配置错误启动失败；相同输入/配置选择相同分支；重试配置快照不漂移。
2. Schema/业务/超时/429 故障注入分别进入正确分支；半开探测、预算耗尽、进程重启、重复领取可回归验证。
3. 审核事务可回滚且幂等；样例刷新排除本课和冻结集；冻结集写入被数据库拒绝。
4. 上传到审核/报告的集成样例共享 traceId，重试 ID 不变；历史回填可重复运行。
5. 场景指标、报告文案、旧快照隔离测试通过；不编造真实错分率改善。
6. 提供迁移、回填/刷新/回归命令、部署与恢复说明。真实数据库不可达时明确区分单元验证与未运行的数据库集成验证。生产迁移不自动执行。
