# Qwen3.7-Flash 开发配置验收

模型：`qwen3.7-flash`；端点：Singapore compatible-mode；预设：`WORKFLOW_MODEL_PROFILE=qwen3.7-flash`。请求发送原生 `response_format.json_schema` 与 `strict=true`。仅保存开发设置，未部署。

## 实测结果

使用用户二进制试讲的 12 句节选；不是完整课堂或人工冻结黄金集。

| 测试 | 真实请求 | 结构结果 | 业务结果 |
| --- | ---: | --- | --- |
| 原生数组小样 | 1 | HTTP 200，数组类型正确 | 仅能力探测 |
| 初次校对→抽取 | 2 | 两阶段 Schema 通过，4 张卡 | 当时缺少两个可选数组，随后将其改为必填；不作为最终业务验收 |
| 注入一次 429 后恢复 | 2（另有一次本地 429） | 无 Schema 失败 | 4/4 通过现有业务守卫；3/4 引用精确匹配 |
| 真实响应数组改成字符串 | 3 | 首次校验拒绝，真实模型重试后通过 | 3/4 通过，1 张被 `oral_confirmation_strength_too_high` 拦截；整次验收不通过 |

后两项使用完整 Schema，配置哈希 `58c4aeb1e567e447f86b2fe0cecd4f1be660424a805022203bbf5c0b76bbd494`。耗时分别为 17.121 秒、27.110 秒。故障是本地注入，后续生成调用真实模型；429 测试不代表数据库持久化恢复验收。

## 结论与边界

严格结构输出能力已证实可用；格式恢复成功不能替代证据业务校验。现有守卫尚未强制所有引用精确匹配，因此不声称无幻觉。不能将本次换模型与换输出模式的结果计算为编排底座单独带来的提升，也不能据此计算抽取召回率。

专用 PostgreSQL 待提供；租约、持久化恢复和数据库端到端验收仍待执行。旧 qwen-max 失败记录保留。开发服务需要加载新代码并重启后才使用预设；已冻结的任务快照不自动变更。
